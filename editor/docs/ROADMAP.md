# Roadmap

Product direction: one workspace for system design, ERD, UML and whiteboarding, with real-time collaboration. We borrow the best ideas from Figma, Miro, Excalidraw and draw.io and keep everything self-hostable.

## Phase 0: stabilise (now)

- Cluster palette items show their real tech logos instead of the empty-square placeholder.
- Finish the frontend↔backend connection: `/api` prefix, auth pages, offline-first sync, `If-Match` conflict modal, sync indicator.

## Phase 1: workspace model (project → folders → files → pages): implemented (since simplified to Project › Files, see Phase 3)
- **Hierarchy:** Workspace › Project › Folder (nested) › File › Page.
  - Today's "project with pages" becomes one *file*.
  - A project holds many files, and files can live in nested folders.
- **File explorer** in the left rail, VS Code-style tree:
  - create, rename, move by drag and drop, duplicate, delete (modal), search;
  - recent and starred files;
  - per-file icon by its dominant diagram type.
- **Tabs:** open several files side by side in a tab bar.
  - Middle-click closes a tab; tabs can be dragged to reorder.
  - Dirty markers show unsaved files, and the open-tab set is restored per user.
  - Split view (two files side by side) comes later.
- **Mixed content in one file:** any page can hold any mix of SDD (architecture), ERD (tables and relations), UML (class, sequence, state, use case, activity, component, deployment) and freeform whiteboard objects.
  - The palette shows all kinds, filterable by mode.
  - Cross-links: a UML class or an ERD table can reference an architecture node, e.g. "this service owns these tables".
- **Storage:**
  - Backend: tables `folders` and `files`, with `pages` inside a file document.
  - `.sdd` stays the single-file export.
  - A new `.sddproj` (zip of files and folders) exports a whole project.
- **Permissions** at project level, with an optional per-file override.

**Status:** implemented (see `docs/backend.md`, `docs/api-client.md`, `docs/sdd-format.md`).
- Done: the data model on server (SQLite + PostgreSQL migration of existing projects) and in the browser (versioned local migration), project / folder / file REST API with `If-Match` file saves and last-writer-wins tree operations, `.sdd` per file and `.sddproj` per project, file explorer (create, rename, drag and drop with drop indicators and cycle prevention, duplicate, delete with counts, filter, starred and recent, kind icons, keyboard navigation, context menus, presence dots), file tabs (middle-click and ⌘W close, drag to reorder, unsaved dot, overflow menu, ⌘⇧T, per-tab undo / selection / viewport, restored per user from localStorage and server preferences), pages as a second row, the palette mode filter (All / Architecture / Data / UML / Board), per-file and project-level WebSocket channels and presence, offline queue for tree operations, per-file role overrides, file and project share links.
- Done: cross-links. A UML class, a component or an ERD table references an architecture node (icon or card) of the same project in `node.data.archRef` (`{nodeId, fileId?, pageId?}`, validated in `lib/serialization.ts`, kept by `.sdd` / `.sddproj`); inspector section "Architecture link" with a picker (this page, other pages, other files), a badge on the node that jumps to the target (opens the file / page, selects, fits), and "Linked from" in the architecture node inspector. A ref whose file, page or node is gone shows as a red "broken link" badge and an inspector warning, never an error. Code: `src/lib/crosslink/`, `src/components/crosslink/`.
- Cross-links not done: one link per node (no many-to-one picker from the architecture side); links are not rewritten when a node is copied to another file; cross-file lookups read the local file store (a file never opened on this device is broken until synced); the text DSL does not print `archRef`.
- Not done: split view (two files side by side, "comes later" in this roadmap); remembering the `.sdd` file handle per tab (switching files forgets which `.sdd` a file was opened from, so ⌘S asks for a location again); a UI for per-file role overrides (API only); multi-select drag and drop in the explorer; a UI for project-level sharing of a single folder.

## Phase 3: real-time collaboration
- **Multiplayer editing** with a CRDT: Yjs document per file; y-websocket provider on the Fastify server; persisted to the database as snapshots plus updates.
  - Offline edits merge automatically, so the `If-Match` conflict modal is only needed for the legacy REST path.
- **Presence:**
  - live cursors with names and colours;
  - selection highlights;
  - "follow user" mode (Figma);
  - avatars in the top bar and the file tree;
  - viewport indicators on the minimap.
- **Audio, and later video, rooms per file:**
  - WebRTC mesh for small groups, with an SFU (LiveKit, self-hostable) for larger ones;
  - push-to-talk or open mic, mute, speaking indicators on avatars and cursors;
  - TURN server config for NAT.
- **Comments:** threaded, pinned to canvas points or objects, @mentions, resolve; notifications.

## Phase 6: smart tooling (no AI)
Everything here is deterministic: parsers, rules and layout algorithms. There are no LLMs and no external AI services.
- **Diagrams as code:** a text DSL with a live split-view, where editing the text updates the canvas and editing the canvas updates the text.
  - It covers architecture (nodes, groups and edges with the icon catalog), ERD (DBML-like), sequence (Mermaid-like), UML class (packages, generics, members, all relation kinds with multiplicities and roles), state (composites, regions, choice / fork / join / history), use case (boundary, include / extend, extension points) and component (ports, nesting, dependencies); the Go port in `Backend/internal/domain/diagram/core` mirrors it (golden tests).
  - Not in the text: UML notes, class attribute-row anchors, port sides, free-standing interface nodes (kept on the canvas); `extends` / `implements` are read but printed as relations.
  - One `.sdd` extension for everything: a ZIP container (`application/vnd.sdd+zip`, manifest `type: file|project`) or the text DSL (`text/vnd.sdd`, first line `#!sdd`), told apart by content sniffing. Legacy `.sddproj` and `.sddt` still open.
- **Infra import:** parse Terraform (HCL + `terraform show -json`), Kubernetes YAML/Helm-rendered manifests, docker-compose and AWS CloudFormation. Map resources to catalog icons, infer edges (references, `depends_on`, Services → Deployments, security groups, env/URLs), group them by VPC/subnet/namespace and auto-layout.
- **Rule-based lint** (Problems panel, opened on demand). Each rule can be configured or disabled:
  - Architecture:
    - single point of failure (one instance or no replica behind a load balancer);
    - database without backup or replica;
    - public service without a WAF or load balancer;
    - cycles in sync calls;
    - missing monitoring edge;
    - cross-AZ issues from cluster profiles.
  - ERD:
    - foreign key without an index;
    - table without a primary key;
    - type mismatch between FK and PK;
    - nullable FK combined with a required relation;
    - naming conventions.
  - UML: inheritance cycles; an interface with no implementation; unused classes.
- **Diagram diff and review:** compare two files or versions structurally (added/removed/changed), comment on a diff, and export a change report.
- **Capacity and latency calculator:** attach rps, payload size and latency to nodes/edges, then propagate along paths. The result shows bottlenecks, worst-case path latency, rough cost per provider from a static price table, and storage growth.
- **Schema tools:** live DB introspection (PostgreSQL/MySQL/SQLite, read-only), migration SQL generated from an ERD diff, seed-data spec export (Seedora `seedora.yaml`).
- **Code ↔ UML sync:** re-import code to update an existing class diagram while keeping positions; mark what drifted.
  - **Status: done** for TypeScript, Java, Python, Go and C# (tests per language). Re-import never replaces nodes: classes match by name, a class that is new in the code but has (nearly) the members of a class that vanished is offered as a **rename** (header line `name: Old → New`, accept renames the same node), so node ids, positions, member ids, `modelId` and `archRef` are kept; relations of a renamed class are compared under the new name.
- **Shared UML model (one class on several pages of a file):** a class node can carry `data.modelId`; every node of the file with the same id is a linked copy. Renaming, kind, generics, stereotype and members change on all copies in one undo step (`updateClass`, also a rename through `updateNodeData`); position, size policy, accent, collapse state, package and `archRef` stay per copy. "Add existing class" in ⌘K places a linked copy; "Unlink from shared class" (context menu / ⌘K) detaches one copy; deleting a copy leaves the others. Sequence lifelines (`participants[].modelId`) and object nodes (`modelId`) can link to the same model ("Link lifelines and objects with this class name"), so their class name follows a rename. A badge with the copy count marks linked copies. **Status: model code done for one file; not reachable in the product yet:** there is no page UI (no way to add a second page), so "Add existing class" is hidden in ⌘K while a file has a single page and only appears once a file has several pages (imported / opened files can still have them). The model code (`modelId`, `addLinkedClass`, `listModels`, unlink) stays. No schema bump (one optional string; the server keeps unknown fields, and checks `modelId` is a string). Limits: not across files (other files live in separate documents and are saved on their own, so a rename could not be one undo step or one Yjs transaction, and a file nobody has open could not be updated), so the picker lists the open file's pages only; the live-collab editor shows page 1 only, so there a model is shared within the visible page; two copies on one page share a class name, which the `.sdd` text cannot express (duplicate class); concurrent edits of the same field on two copies by two people are last-writer-wins per copy (different fields, and positions, merge).
- **MCP server for external AI clients** (the product itself has no AI). Ship an MCP server (`server/mcp`, stdio and streamable HTTP) so tools like Claude can read and edit diagrams through a typed, permissioned API.
  - Read tools: `list_projects`, `list_files`, `read_file` (nodes/edges as JSON).
  - Edit tools: `create_file`, `add_nodes`, `add_edges`, `update_node`, `delete_elements`, `apply_layout`, `search_catalog` (icons, clusters).
  - Format tools: `import_dsl`, `export` (Mermaid/PlantUML/SQL/SVG), `run_lint`.
  - Auth: personal access tokens with scopes (read / write per project).
  - Every change goes through the same validation and Yjs path, so live collaborators see AI edits in real time, attributed to "<user> via MCP", and they are undoable.
  - Rate limits and an audit log.
  - Docs with a Claude Desktop / Claude Code config example.
- **Smart layout:** more algorithms (layered, orthogonal, radial, tree, force-directed, compact grid), "tidy selection", align by groups, and label overlap removal.

**Status: implemented** (see `docs/smart-tools.md`, `docs/mcp.md`, `docs/sdd-format.md`, `CHANGELOG.md`).
- Done: MCP server (stdio bridge + streamable HTTP, 14 tools, scopes, per-project tokens, rate limit, audit table, live Yjs writes attributed "<user> via MCP", `undo_last_change`); diagrams as code (`.sdd` text for architecture, ER and sequence; CodeMirror 6 split view with two-way sync, inline diagnostics, icon autocomplete, positions preserved); the unified `.sdd` extension (ZIP file / ZIP project / text, content sniffing, `source.sdd`, legacy `.sddproj` and `.sddt` still open, same safety limits); infra import (Terraform HCL and `show -json`, Kubernetes / Helm, docker-compose, CloudFormation, dialog with preview); 15 lint rules with per-rule settings and quick fixes; diff and review (property-level changes, comments, Markdown report); capacity and latency (schema v8, bottlenecks, worst-case path, storage growth, labelled cost estimate); schema tools (live PostgreSQL / MySQL / SQLite introspection, migration SQL per dialect, `seedora.yaml`); code to UML drift review with accept / reject; six layout algorithms, tidy selection, label overlap removal, align groups.
- Not done / limits: Seedora's own YAML schema is unknown, so `seedora.yaml` carries this tool's `seed` vocabulary; cost prices are generated from the official AWS/Azure pricing APIs (`make prices`; GCP only with `GCP_BILLING_API_KEY`); migration SQL renames are matched by shape or diagram id (a shape match is a guess: review it), a rename that also changes the type needs ids; every page of a file is live-synced over Yjs but the editor shows page 1 only (the MCP tools take `pageId`); the lint and capacity rules know common catalog ids only (unknown icons count as services); drift detection treats associations drawn by hand as not-stale; the PostgreSQL / MySQL introspection is tested against catalog-row fixtures, not a live server; `elkjs` was not needed.

## Cross-cutting
- Performance: virtualised rendering for more than 5k nodes, and worker-based routing.
- Accessibility: keyboard-only editing and a screen-reader outline view.
- Self-hosting: single container, Helm chart, S3 storage, SSO (OIDC/SAML).
- Testing: TDD; Playwright end-to-end and visual regression for templates.

**Status: implemented** (see `docs/self-hosting.md`, `CHANGELOG.md`).
- **Testing: done.** `make e2e` (`npm run e2e`; `make e2e-update` regenerates baselines) builds the frontend and runs Playwright against the real backend (Fastify + SQLite in a temp dir, one free port, Chrome from the machine, no browser download). It is not part of `make check` (minutes, needs Chrome). Specs: landing -> projects -> new project, palette icons, connecting an edge, renaming (project and node), `.sdd` export / import round trip, ⌘K, a private sticky that a second user (second browser context) never receives, 58 visual baselines (29 templates x light / dark, 2% pixel threshold, stable on a second run), the performance benchmark and the axe / keyboard checks. The MCP path is not exercised by e2e (covered by the server tests).
- **Performance: done, with limits.** Fixture: `src/lib/bench` (`npm run bench:fixture`, 5k nodes / 11.9k edges and 10k nodes / 15.7k edges). The editor's `localStorage` copy of a file (about 5 MB per origin, a failed write is swallowed) caps a page at roughly 4.5 MB of JSON, so the 10k fixture is sparser than the 5k one and about 10k such nodes is the ceiling of the browser store. Measured in headless Chrome on the dev laptop (`e2e/perf.spec.ts`):

  | | before | after |
  |---|---|---|
  | 5k: file handed to the app until nodes are on screen | 145.7 s | about 2 s |
  | 5k: nodes in the DOM | 5000 | 48 (`onlyRenderVisibleElements` above 1000 nodes) |
  | 5k: pan, 90 synthetic mouse moves | 8 of 90 done in 35.5 s, frame avg 814 ms, p95 3.5 s | 90 in about 15 s, frame avg about 100 ms, p95 167 ms |
  | 5k: longest main-thread task | 46 s | about 2.1 s |
  | 10k: first render | none within 240 s | about 3 s, longest task 4.3 s |
  | `computeRoutes`, 5k nodes (node, no browser) | 11 s first layout, 2.3 s per dragged node | 0.3 s first layout (3.7 s with long hops in the fixture), 60 - 120 ms per dragged node |

  What changed: `absolutePosition` / `ancestorsOf` / `junctionEnds` rebuilt an id index per call (routing was O(N^2)); obstacles come from a bucket grid (`routing/spatial.ts`), track separation and clash checks look at neighbours only; above 3000 edges routing is in "fast" mode (3 ms per edge, one padding attempt, no side-combination search: long edges may fall back to simple steps); pages above 600 edges are routed in a Web Worker (`routing/worker.ts`, `async.ts`: only changed routes come back, requests are coalesced, synchronous fallback in jsdom / without Worker); node components are memoized; alignment data is computed for the selected edge only. The route cache that invalidates by neighbourhood (moved node, old and new position) already existed and now lives in the worker. The budgets in the test are deliberately loose (initial 15 s / 25 s, pan p95 300 ms, longest task 6 s / 10 s) because the frame times include the automation round trip of every mouse move; a CPU profile of the pan is about 85% idle. Limits: pan and drag frame times are still above 16 ms with the full pipeline on 5k+ nodes (the per-update edge styling in the canvas is O(edges) on the main thread, and `lint` / Yjs work run on every change); dragging on huge pages shows the old routes for a few frames until the worker answers.
- **Accessibility: done, with limits.** Tab walks the nodes (React Flow); Alt+arrows move focus and selection to the nearest node (45-degree cone); arrows nudge (Shift = 10); Enter edits the label; Shift+C starts connect mode (source = focused node, pick the target the same way, Enter connects, Esc cancels, announced in a live region); Delete / Escape as before; a focus ring on nodes and edges; the outline (Shift+O, View menu, ⌘K "Outline") lists pages > nodes (groups nest) > connections as an ARIA tree, hidden by default. axe (`@axe-core/playwright`, WCAG 2 A / AA tags) runs in e2e on landing, login, register, projects, the new-project dialog, the editor, the palette, ⌘K, the outline and an ER and a UML template; serious / critical findings fixed (button names that did not contain their visible text, ARIA labels on non-interactive grips). Limits: only those screens are scanned (not every dialog or the board / sequence editors), axe cannot judge colour contrast of canvas content or screen-reader quality, and the canvas itself is still a pointer-first surface (resizing, waypoints and freehand have no keyboard equivalent).
- **Self-hosting: done, with limits.** One multi-stage image (`Dockerfile.server`: frontend + backend, one port, non-root, `/healthz` health check). Helm chart `deploy/helm/sdd` (Deployment, Service, optional Ingress, PVC or `DATABASE_URL`, probes, Secret or `existingSecret`, restricted security context). S3-compatible storage behind the storage interface (`S3_BUCKET` selects it; `@aws-sdk/client-s3` 3.700.0; tested with a mocked client). OIDC (authorization code + PKCE, discovery, e-mail mapping, optional auto-provisioning and domain allow-list; `openid-client` 6.8.8; tested against a fake IdP that validates PKCE and signs ID tokens). SAML 2.0 SP-initiated (`@node-saml/node-saml` 5.2.0, which is actively maintained; signature, audience, InResponseTo, replay and validity checks; tested with signed fake responses and forgeries). Docs: `docs/self-hosting.md`. Limits: `helm lint` / `helm template` were not available (the chart has a static test only, it was never installed on a cluster); one replica only (live co-editing is single-process); no IdP-initiated SAML, encrypted assertions, single logout or RP-initiated OIDC logout; S3 and SSO were tested against fakes, not against a real MinIO / Keycloak / Okta; existing local files are not migrated to S3 automatically.
